# DC-027.5 — Parity verification and evidence

## Story

As a delivery owner, I want reproducible HTML, screenshot and accessibility
evidence, so that parity is accepted only when the stated thresholds are met.

## Acceptance Criteria

1. The comparator reports body HTML >=90% and visual >=97% at 375, 768 and
   1440 CSS px; no threshold is inferred from a single viewport.
2. Evidence includes reference/local screenshots, diff images, metrics,
   heights, console errors, missing assets and overflow status.
3. A WCAG report records contrast, focus, labels, keyboard and reduced-motion
   findings, with failures blocking completion.
4. The story and Second Brain record the final measured values and any residual
   limitations; no “complete” claim is made without artifacts.

## Tasks / Subtasks

- [ ] Run body comparator excluding scripts (AC: #1, #2).
- [ ] Run Playwright/Puppeteer screenshots and pixel diff at three viewports
  (AC: #1, #2).
- [ ] Run WCAG/axe and contrast checks (AC: #3).
- [ ] Attach evidence and update the parity decision record (AC: #4).

## Dev Notes

- Use `bashscripts/tools/visual/compare-body-html.mjs` and
  `compare-screenshots.mjs`; controlled image stubbing is diagnostic only and
  must be reported separately from raw parity.
- The verification matrix is 320/390/768/1024/1440 for responsive behavior,
  with 375/768/1440 as the parity screenshot gate. [Source: `bmad-output/front-office-design-comuni/architecture.md#Responsive and accessibility contract`]
- Stories are complete by countable evidence, not by a subjective visual claim.
  [Source: `bmad-output/front-office-design-comuni/prd.md#Delivery rule`]

## Testing

- **Approach:** end-to-end browser comparison plus WCAG audit.
- **Key scenarios:** default query, empty results, mobile filter state and
  rating interaction.
- **Fixtures / mocks:** official reference URL, local route and JSON fixture.
- **Edge cases:** network-idle timeout, external image variance and debug bars;
  report each rather than silently masking it.

## Dev Agent Record

### Verification update — 2026-10-13

- Playwright screenshots were captured at 375, 768 and 1440 CSS px, comparing
  the official reference with the local route. After restoring the responsive
  container/grid geometry, full-page parity is 82.26%, 77.97% and 80.41%
  respectively. The release gate is still open because shared shell/footer
  geometry and vertical rhythm remain different.
- The focused search CTA comparison is 91.22% at all three widths. Its
  computed resting state is green `rgb(0, 122, 82)` with white text, matching
  the reference; hover and focus-visible retain a green background instead of
  changing from white.
- The result-card geometry now matches the reference at all tested widths
  (mobile/tablet container widths and desktop 330/110/880 grid). The next
  parity work must address the shared header/footer and the vertical rhythm
  below the results, while preserving the generic `[slug]` route.
