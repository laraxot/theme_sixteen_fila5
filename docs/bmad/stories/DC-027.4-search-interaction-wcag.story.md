# DC-027.4 — Alpine interactions and WCAG

## Story

As a keyboard and mobile user, I want filters, search and rating controls to
remain understandable and operable, so that the page is usable without a mouse.

## Acceptance Criteria

1. Filter controls have labels, field grouping and visible focus; the mobile
   filter disclosure exposes the same options as desktop.
2. Search submit, load-more and rating controls have accessible names and
   deterministic Alpine state with a no-JS readable fallback.
3. Contrast, focus visibility, target size, reduced motion and heading/list
   semantics satisfy WCAG 2.1 AA checks.
4. No `data-bs-*`, Bootstrap JS, or Bootstrap Italia runtime is introduced.

## Tasks / Subtasks

- [ ] Implement Alpine filter disclosure and load-more state (AC: #1, #2).
- [ ] Implement rating state with keyboard semantics and `aria-live` feedback
  (AC: #2, #3).
- [ ] Audit contrast/focus/target sizes and correct tokens (AC: #3).
- [ ] Search the rendered asset graph for Bootstrap runtime references (AC: #4).

## Testing

- **Approach:** axe/WCAG audit, keyboard walkthrough, Playwright interaction
  checks at mobile and desktop.
- **Key scenarios:** open/close filters, submit search, select rating, escape
  dialogs, tab through every control.
- **Fixtures / mocks:** populated JSON and empty-results variant.
- **Edge cases:** reduced motion, 320px viewport and long translated labels.
