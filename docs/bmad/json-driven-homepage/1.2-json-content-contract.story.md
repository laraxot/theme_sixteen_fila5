# Story

Come editor, voglio un contratto JSON esplicito per la homepage, così che ordine,
locale, tipo, view e dati siano modificabili senza cambiare la Folio page.

## Acceptance criteria

- [ ] `config/local/fixcity/database/content/pages/home.json` è presente e valido.
- [ ] Il payload contiene solo le tre funzioni della Blade legacy: hero/mappa/CTA,
  how-it-works e tracking.
- [ ] Ogni blocco ha `type` e `data.view` oppure è classificato come legacy.
- [ ] La struttura localizzata `content_blocks[locale]` copre i locale pubblici.
- [ ] `map-preview.data.list_url` usa
  `{{ route('container0.index',['container0' => 'tickets']) }}`, non `/tickets`.
- [ ] `map-preview.data.report_url` usa
  `{{ route('container0.view',['container0' => 'tickets','slug0' => 'create' ]) }}`;
  non usare `/tickets/create`, `container0.create`, `container0.store`,
  `tickets.create` o `LaravelLocalization::localizeURL('/tickets/create')`.
- [ ] I blocchi senza view esistente sono elencati, non nascosti con fallback.

## Tasks

- [ ] Validare JSON e locali (AC: 1–3).
- [ ] Verificare le view indicate rispetto al catalogo Sixteen (AC: 2, 4).
- [ ] Produrre elenco gap per story 1.3/1.4, senza inventare blocchi marketing (AC: 2–4).
