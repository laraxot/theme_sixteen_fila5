## Problem
The browser reports 404 errors for several static assets:

- `themes/Sixteen/css/MarkerCluster.Default.css`
- SVG sprites from `design-comuni/assets/bootstrap-italia/dist/svg/sprites.svg`
- Various SVG icons under `assets/fixcity/svg/*`
- Livewire assets being out‑of‑date.

These files are not present in the public folder because they are generated by the **Vite** build pipeline or need to be copied from `node_modules` / theme assets.

## Fixes
1. **Re‑run the asset build**
   ```bash
   cd laravel/Themes/Sixteen
   npm ci            # ensure node_modules are fresh
   npm run dev        # compiles CSS/JS and writes to public_html/themes/Sixteen
   ```
   This will generate the hashed CSS files (including the `MarkerCluster` CSS) and update the manifest.

2. **Copy static assets**
   The package includes a helper script that copies required CSS and SVG files to the public directory:
   ```bash
   npm run copy
   ```
   The script (see `package.json` → `scripts.copy`) creates the `public_html/themes/Sixteen/css` folder and copies:
   * `node_modules/leaflet.markercluster/dist/MarkerCluster.css`
   * `node_modules/leaflet.markercluster/dist/MarkerCluster.Default.css`
   * Bootstrap‑Italia SVG sprite
   * Project‑specific SVG icons (logo‑comune.svg, logo‑eu‑inverted.svg, etc.)

3. **Publish Livewire assets**
   ```bash
   php artisan livewire:publish --force
   ```
   This refreshes the Livewire JavaScript and CSS in the public folder.

4. **Clear compiled views** (already done during the route error fix):
   ```bash
   php artisan view:clear
   php artisan route:clear
   ```

## Recommended workflow
- After any change that adds a new CSS import, run `npm run dev` (or `npm run build` for production).
- If you add new static SVGs or other files, extend the `copy` script in `package.json`.
- Keep the **manifest.json** in sync – Vite will automatically update it when assets are rebuilt.
